<objective>
Die Regelhälfte des Trockenlauf-Kommandos: ein Modul mit reinen Funktionen, das ein vorgelegtes Token gegen eine übergebene Exchange-Konfiguration prüft und eine Liste benannter Schritte mit je einem benannten Ergebnis zurückgibt. Keine Route, keine Umgebung, kein Nextcloud-Aufruf, keine Sitzung, keine Audit-Zeile.

Purpose: Erfolgskriterium 3 verlangt ein benanntes Ergebnis je Prüfschritt und verbietet dem Token ausdrücklich jede Wirkung. Die Regel gehört zum Prüfer und die Konsole zur Shell (24-RESEARCH.md, D3), genau wie `audit/store.verify_chains` die Regel hält und `exapp/audit_verify.py` die Konsole.

Entschieden in diesem Plan (Open Question 2 der Recherche): die Regel wird so gebaut, dass eine zweite Oberfläche später nur noch eine Datei ist. In dieser Phase bekommt nur der ExApp-Betrieb eine Oberfläche (occ, Plan 24-06); der Standalone-Betrieb bekommt keine, und die Grenze wird in `docs/token-exchange.md` (Plan 24-09) ausdrücklich benannt statt stillschweigend gelassen.

Output: `oauth/exchange_dryrun.py` plus ein Drift-Gate, das strukturell ausschließt, dass der Trockenlauf grün sagt, wo der Betrieb rot sagt.
</objective>
